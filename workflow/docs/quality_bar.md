# Workflow Quality Bar v1

## Stage 1
- Must stay product-level only
- Must include explicit acceptance_criteria
- Must not mention code implementation

## Stage 2
- Every requirement must include id, module, description, priority, verification
- Must separate functional and non-functional requirements

## Stage 3
- Must inspect repo before output
- Must provide at least 3 evidence-backed findings
- Must distinguish evidence vs inference
- Must map requirement IDs to likely code areas

## Stage 4
- Must provide at least 2 solution options
- Must recommend one option
- Must address dual-stack risk if present

## Stage 5
- Every task must be atomic
- Every task must include dependencies and deliverables
- Must include acceptance gates

## Stage 7
- Must identify schema drift
- Must propose at least 3 concrete improvements
